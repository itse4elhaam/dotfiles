# Desktop dictation

On Pop!_OS/X11, place the caret in an editable field, hold **Super + Left Alt**, speak, and release either key. Both press orders work. A blue–lavender glow outlines the window you started in. Its lower edge swells with the microphone, then disappears when capture stops. Moving focus clears the outline. The bottom card shows the live transcript above its waveform in T3’s Inter typeface. Press **Esc while holding the shortcut** to discard the recording.

Run `apps/desktop-dictation/install.sh` from this checkout to install or update the user service. It uses the system Python 3.10 with GTK 3, PyGObject, pycairo and python-xlib, PulseAudio-compatible `parec`, and the Linux x64 T3 Code Nightly AppImage in `~/Applications`. Download **Parakeet Unified English 0.6B** and the Silero silence filter through T3 once. T3 can be closed during dictation.

The worker reads T3’s installed Q8_0 GGUF and Silero v6.2, streams locally, and applies the filler-word, silence-filter and preferred spelling/alias settings from `~/.t3/userdata/client-settings.json`. The model supplies punctuation. Cleanup also recognizes explicit numeric repairs such as “set it to 42, sorry, 24”. No cloud text-generation pass runs. Audio stays in process memory. After a successful recording the model stays warm for 15 idle minutes. If recognition fails mid-utterance, the last available partial can be copied from the overlay. In applications that use clipboard paste, dictation briefly serves the transcript, then restores the previous clipboard formats. Clipboard managers can retain paste history. An unsupported clipboard format or an oversized selection stays untouched and the overlay offers Copy.

Clicking or typing during finalization, switching windows, or changing fields with the mouse leaves the transcript in the overlay. Choose **Copy** to copy the displayed transcript or **×** to dismiss it. Unhandled transcripts stay available, newest first, until you copy them, dismiss them, or lock the session.

In Google Chrome, Chromium and T3 Code, dictation types directly into the focused editor and leaves the clipboard alone. Keep the caret in an editable field. X11 identifies the focused window, while the browser decides which element receives keystrokes. Direct typing supports up to 256 printable characters per recording. Dictation checks every character against the active keyboard layout and Caps Lock before typing. Accented letters work when the layout can produce them with a single plain or Shift keystroke. Longer transcripts, tabs, newlines, and characters that require Compose, dead keys or AltGr go to **Copy** in full.

Direct GTK 3 paste requests carry the timestamp of the V keypress. Dictation checks this against the XInput event from the shortcut it dispatched. A second X connection from the same local process can receive the transcript if it supplies the original V timestamp. Dictation checks the process identity with X-Resource 1.2. If the focused process cannot be identified, the overlay offers **Copy** immediately. Readers that request fresh server time or use X11 CurrentTime (including arboard-style clipboard reads) receive empty text and get **Copy** after the timeout.

Within the same key handler, an independent read can carry exactly the same timestamp, requestor window, and target as the field’s paste. Both reads can receive the same transcript until the 1.8-second delivery window ends or another dictation clipboard operation starts. Later reads bearing that gesture’s timestamp from the same process receive empty text while dictation owns the selection. X11 cannot confirm insertion into a field, so the latest acknowledged transcript stays available through **Copy** until replaced, copied, dismissed, or cleared by locking. Other applications can read the restored clipboard independently.

The service remembers at most 65,536 acknowledged timestamps and process identities. A timestamp collision after X11 clock wrap falls back to empty text and recovery. At capacity, future clipboard deliveries use **Copy** until the service restarts. The private Xvfb test exercises these cases with a GTK entry and a second X connection. Chrome 143 uses CurrentTime for an ordinary HTML input, which is why dictation uses direct typing there.

A second hold can record while the first field is reading its paste. If the application does not make a matching read within 1.8 seconds, automatic pasting pauses for that application. Both transcripts remain available through **Copy**. The pause also applies to later holds in that application. While dictation owns the restored clipboard, text reads from the paused application return empty. Other applications continue to see the previous clipboard during automatic delivery.

Choose **Copy** to make the transcript available in other applications immediately. X11 cannot tell which field in the paused application requested clipboard text. Every text read from that application therefore stays empty while dictation serves the copy. Once the application has finished handling its old shortcut, choose **Resume** on the card for that application, then paste into the intended field. Resume also allows automatic paste on future holds. Dismissing the card keeps the application paused. An external clipboard owner continues to serve its own data.

Applications can move their own caret or switch internal fields without notifying X11. Keep the caret in place until the overlay finishes. Auto-paste uses Ctrl+V in GUI applications and Ctrl+Shift+V in common terminal emulators. The recording limit is five minutes.

In xterm and urxvt, choose **Copy** in the overlay, then paste with your terminal’s CLIPBOARD binding. In xterm, Shift+Insert reads the selection configured by `selectToClipboard`, which defaults to PRIMARY. In urxvt, Ctrl+Meta+V reads CLIPBOARD, but each terminal instance can choose which modifier acts as Meta. Dictation sends no paste keys to these terminals. [xterm manual](https://invisible-island.net/xterm/manpage/xterm.html#VT100-Widget-Resources:selectToClipboard) · [urxvt manual](https://manpages.debian.org/bookworm/rxvt-unicode/urxvt.1.en.html#THE_SELECTION)

Set `T3_DICTATION_APPIMAGE=/absolute/path/to/T3.AppImage` in `~/.config/desktop-dictation.env` if T3 moves. Restart with `systemctl --user restart desktop-dictation`. For diagnostics use `journalctl --user -u desktop-dictation`. Disable with `systemctl --user disable --now desktop-dictation`.

Run `/usr/bin/python3 apps/desktop-dictation/test_x11.py` with Xvfb and xdotool on PATH. Add `--chrome` to check a real HTML input and contenteditable in a temporary Google Chrome profile with simulated recognition. The Chrome test also requires setxkbmap. Add `--real-model` for recorded English audio through the bundled worker. The test starts its own X server and supplies microphone fixtures.
